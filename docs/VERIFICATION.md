# Verification matrix

Run commands from the repository root using pnpm. Scripts in `package.json`, test projects in `vite.config.ts`, CI in `.github/workflows/ci.yml`, and applicable scoped `AGENTS.md` files are authoritative. Use [the task-to-file map](REPO-MAP.md) to find affected tests and consumers.

## Select checks without repeating work

- Combine every applicable row below. Start with the smallest relevant test during development, then run the checks warranted by the final diff. Scoped requirements still apply.
- Build before standalone tests/typechecks on a fresh checkout: `pnpm build` is the documented baseline because consumers resolve built package exports. In an already-built workspace, rebuild changed libraries and their prerequisites before checking consumers. Reuse successful check results only if relevant source, configuration, dependencies, and build outputs have not changed.
- Browser iteration is different: playground/UI source and styles hot-reload through development exports and the source-CSS alias, without rebuilding or restarting. That does not update built exports/declarations or prove production/package behavior. Use focused checks during iteration and the combined final gates for the change type; see the [fast development loop](../AGENTS.md#fast-development-loop).
- Use `pnpm --filter '@ljay/ui...' build` for a dependency-inclusive library build, replacing the name as needed. Use `pnpm --filter @ljay/ui typecheck` for a scoped TypeScript check. Brand/tokens have no typecheck script, and no workspace has a test script; run focused tests through root `pnpm test <file-or-path>`.
- Stop task-owned development servers before clean builds. Do not replace outputs consumed by another task's servers; use an isolated source copy if needed. See [application guidance](../apps/AGENTS.md#isolated-development) for port and process ownership.

## Final integration and reporting

- `pnpm ready` is the full CI gate: check, build, typecheck, coverage tests, package-consumer checks. `pnpm test:coverage` runs the full suite with V8, requires at least 90% aggregate coverage for each of statements, branches, functions, and lines, and then validates the report's authored-source inventory through `scripts/check-coverage.mjs`. See [coverage scope and reports](../README.md#test-coverage). A threshold failure remains blocking even if all tests pass; do not lower thresholds or narrow the source denominator to hide it. Prefer the full gate for final source-change integration when practical; focused results are not equivalent to a full CI pass. Do not rerun its constituent checks immediately beforehand solely to duplicate coverage.
- Package-consumer checks create and retain a temporary consumer and may need registry access or an existing store. Use `TMPDIR=/tmp/opencode pnpm test:packages`, or `TMPDIR=/tmp/opencode pnpm ready` when running the full gate. If prerequisites are unavailable, report the blocked check rather than installing unrelated tools, bypassing checks, or claiming a pass.
- Packaged README/consumer-agent guidance changes require `pnpm check` and the package-consumer check, including README presence, packaged local links, and the opt-in `AGENTS.md` discovery fixture. Reuse unchanged build prerequisites; combine executable tooling changes with the root-tooling row. No browser rerun is needed for prose-only package guidance without changed UI/assets.
- Automated jsdom tests and the catalog's width control do not replace browser validation. Limit browser checks to affected flows; record what was actually exercised and any gaps.
- Report commands and actual outcomes, plus required checks that failed, were blocked, or were not run. Distinguish targeted validation from the full gate and pre-existing failures from regressions. Do not claim source-change readiness while required checks remain blocked.
- Maintain this matrix and affected scoped guidance in the same change when commands, build prerequisites, test projects, or verification requirements change. Keep instructions aligned with manifests and CI; do not invent package scripts.
