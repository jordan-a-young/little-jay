# Component playground

- Read `docs/CATALOG.md` before catalog changes and `docs/BRANDING.md` before theme/bootstrap/asset changes.
- Components belong in `packages/ui`; catalog pages, executable examples, authored props/snippets, registry metadata, and preview controls belong here. Update documentation alongside changed component contracts.
- Preserve stable page/example IDs, hash deep links, Back/Forward, missing-route recovery, and lazy category loading. Add pages through `src/catalog/registry.ts` and the existing page/example pattern.
- Keep the catalog sidebar left of documentation even on narrow screens. The dynamic-viewport shell has a sticky header and separate, keyboard-focusable sidebar/content scrollers with scroll containment; do not restore document scrolling, stacked navigation or a nested sidebar-nav scroller incidentally. Layout contract tests live in `src/catalog-layout.test.ts`; verify actual scrolling/focus and narrow layouts in Chrome.
- TanStack Router is configured directly in `src/router.tsx` with hash history and one optional-example route; do not add a shared router package or reintroduce a custom route observer/parser. `src/routing-history.ts` only adapts legacy/malformed inbound locations. Keep the root shell mounted, clear optional example params on page links, and preserve selector focus on example changes. Route context uses the same QueryClient as QueryClientProvider; do not add health prefetch or another data cache incidentally.
- `catalog/ExampleTabs.tsx` owns the manual underline example selector: route-controlled selection, RTL-aware wrapping arrow/Home/End focus, native Enter/Space activation and horizontally scrolling bounded labels. Keep stable tab/panel associations, focus on surviving tabs, no selection on missing example routes and only the active preview/code mounted. Do not reuse shared Tabs' visited-panel caching or change preview reset/deep-link/history semantics incidentally. Colocated component tests and catalog/router tests cover this boundary.
- Demos are local-only unless explicitly demonstrating a real API operation. Label simulations; do not start workflows, persist records, or add external calls incidentally.
- WorkflowForm composes Button + LoadingIndicator for pending local validation; stacked app-owned labels reserve both states' size. Keep one live status outside the busy form, the spinner decorative, reduced-motion behavior and useFormStatus/useActionState ownership. Preserve disabled-fieldset, drafts and conditional focus recovery; do not add a pending Button API, new timer or invented progress.
- PasswordField examples live with Forms at `/#/password-field`, `/controlled` and `/states`. Use synthetic local values only, current/new-password autocomplete intent, native reset and caller-owned controlled reset handling. Never show real credentials, log/echo values, submit to an endpoint or add authentication policy to the shared control.
- NumericInput examples live with Forms at `/#/numeric-input`, `/controlled` and `/states`. Use synthetic local integer settings, distinguish drafts/commits from saves, and demonstrate invalid restoration, same-value rerenders, native FormData/reset and app-owned controlled updates without requests or persistence.
- Tabs examples live with Inspection at `/#/tabs` and `/#/tabs/controlled`: demonstrate manual activation, disabled triggers, preserved local draft state and caller-controlled selection without changing Graph Workbench or adding requests.
- Combobox examples live with Forms at `/#/combobox`, `/controlled` and `/states`. Keep the fictional project list local, selected-ID FormData inspection/reset and caller-owned controlled selection/reset. Existing small NativeSelect settings stay unchanged; do not add remote search or persistence.
- Card examples live with Inspection at `/#/card` and `/#/card/minimal`. `shell/PreviewFrame.tsx` also uses shared Card/CardContent for the outer preview surface; keep preview width constraints and keyed local reset app-owned. Do not restore duplicate outer border/padding/background rules in catalog CSS or add Card landmarks/focus stops merely for styling.
- Table examples live with Inspection at `/#/table` and `/#/table/empty`. `catalog/DocumentationPage.tsx` uses the same shared primitives for its named keyboard-scrollable props reference. Keep catalog column minimums app-owned; do not restore duplicate native-table styling or add sorting/filtering dependencies for the static reference.
- Breadcrumb examples live with Inspection at `/#/breadcrumb` and `/#/breadcrumb/long`. `catalog/CatalogBreadcrumb.tsx` adopts the shared primitives below the page header via DocumentationPage, and in CatalogNotFound. Use Introduction → page → explicit example, omitting redundant Introduction links and category labels without routes. Keep missing-page/example labels plain, ancestor current markers off, and routing/focus/preview state app-owned.
- TanStack Query owns request caching/lifecycle; use `@littlejay/http` for bounded decoded JSON and pass the Query abort signal. Do not add library-owned retry/cache behavior.
- The Foundations hooks guide (`src/catalog/foundations/hooks.tsx`) is a source walkthrough, not a live API consumer. Keep its raw source snippets aligned with their owners and do not mount a health observer merely to display documentation.
- Preserve document-level theme ownership, pre-render bootstrap, persistence fallback, and portal inheritance. Do not remount forms on theme changes.
- Ordinary playground and UI component source, Tailwind-class, and component-CSS edits hot-reload in the development server; do not restart or rebuild just to view them. UI `development` exports and the development-only stylesheet alias provide this behavior. Preview/production and built declaration checks are separate; follow the [fast development loop](../../AGENTS.md#fast-development-loop).
- `branding.ts` synchronizes an allowlist from canonical brand assets. Do not edit or manually populate generated `public/branding/`.
- Run focused tests with `pnpm test apps/playground/src` from the root after building prerequisites. Select browser checks using the [risk policy and representative checklist](../../docs/VERIFICATION.md#browser-risk-policy): check changed interactions/accessibility, visuals and layout in representative conditions, not every state/theme/viewport combination. Prose/tests/type-only changes and proven behavior-preserving refactors may skip browser checks with recorded evidence; a changed layout/control may not. The preview width control is not a real viewport. Preserve feature-specific acceptance checks, including actual pane scrolling when changing the shell.
