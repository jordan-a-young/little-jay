# React UI

- Target React 19; preserve React/React DOM as peers. Use native controls and ref props, existing composition patterns, and Radix only for the established modal foundation. Avoid adding a form library or global state for generic controls.
- Preserve native semantics, accessible names, keyboard/focus behavior, disabled states, field associations, and safe rendering of untrusted text. Accessibility flags are not authorization or server validation.
- Shared UI owns presentation, not workflow policy, network requests, caches, or application schemas. Examples and authored prop documentation live in `apps/playground`.
- PasswordField composes Input with a non-submit visibility action. Ref/className/style target the native input; Field associations belong only to the input and the button keeps its own name. Preserve the same node/value/name/selection, native disabled/read-only/fieldset behavior and uncancelled current-form reset masking. Keep visibility local; no value store, password policy, logging, clipboard interception or authentication logic. Source/tests live in `src/password-field/`, with Forms examples and reset-free tarball fixtures.
- LoadingIndicator is presentational: visible `label` text is optional, icon-only rendering retains hidden loading text, and live roles/busy state remain caller-owned. Keep its reduced-motion fallback and reset-free styles covered when changing it.
- Card and its Header/Content/Footer helpers are native div composition primitives, with no provider, implicit landmark, heading level, focus stop or card-wide action. Keep root padding absent and optional section padding explicit; caller-owned headings and controls retain native behavior. Source/tests live in `src/card/`, with Inspection catalog examples and real outer-preview adoption.
- Table helpers preserve native table/section/row/cell/caption semantics; TableHeader is thead and TableHead is th (default column scope). Optional TableScroll requires a nonblank accessible name and fixes its region/focus semantics. Keep data, column sizing, empty/loading/error content and engines caller-owned. Source/tests live in `src/table/`, with Inspection examples and real catalog props-table adoption.
- Breadcrumb is router-independent native nav/ol/li/span composition. Keep one plain current-page span, decorative separators inside list items and native/router-aware ancestor links caller-owned. Preserve native hidden behavior in flex styles; do not add a router, provider, generated hierarchy or collapsing menus. Source/tests live in `src/breadcrumb/`, with Inspection examples and real CatalogBreadcrumb adoption.
- Tabs uses stable data items, manual horizontal activation and roving focus, with linked named panels. Mount content on first activation and preserve it while its item remains; hidden effects, external-selection focus recovery and responsive layout stay caller-owned. Preserve disabled/RTL keyboard behavior, controlled selection and explicit fallback semantics. Do not turn it into a graph selector or workflow store.
- Styles use semantic tokens and compile into reset-free CSS. Consumers must not need Tailwind. Preserve CSS side effects, theme convenience exports, and the development source/production output boundary.
- The playground development server consumes UI component source through the package's `development` exports and aliases the stylesheet to source CSS. Component logic, Tailwind classes, and component CSS hot-reload without a manual rebuild/restart. This does not refresh `dist` declarations or packaged output; rebuild for checks/consumers that require those artifacts, not for each visual iteration.
- New component exports must be wired through `src/index.ts`, `package.json`, and `vite.config.ts` build entries as appropriate; add catalog examples and tests.
- Run `pnpm test packages/ui/src` from the root after prerequisite builds. Test interactive behavior in jsdom component tests; select browser checks using the [risk policy and representative checklist](../../docs/VERIFICATION.md#browser-risk-policy). New/custom controls and rendering/style/interaction/accessibility changes require targeted checks. Cover each affected behavior once, sample themes/layout where affected, and avoid a full state/theme/viewport product. Verify modal focus restoration and portal theme inheritance when affected. Record evidence for low-risk skips; automated/package-consumer gates still apply.
- For public API/CSS/export changes, also run the package-consumer check described in `../AGENTS.md`.
