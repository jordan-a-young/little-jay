# Repository scripts

- `install-actionlint.sh` installs checksum-pinned actionlint 1.7.12 into ignored `.tools/`; `check-workflows.ts` runs it with a bounded timeout and fails closed if unavailable. ShellCheck/Pyflakes integrations are deliberately disabled for a consistent toolchain; do not silently introduce optional external validators. `check-workflows.test.ts` covers trigger policy, real malformed-workflow rejection, runner failures and isolated installer failures without network access.

- Read the owning contract and `docs/RELEASING.md` for release work. Keep scripts ESM and package-manager execution on the pinned pnpm; preserve root test configuration and exact dependency conventions.
- `release.mjs` owns release guards and local/CI orchestration; `package-artifacts.mjs` owns version-aware tarball filenames. `release:validate` is read-only and permits an empty note set. `release:version` writes only versions/changelogs/lockfile; `release:check` verifies/packs ignored `.release/` output and snapshots per-version metadata targets from validated ancestral tags, never uploading. `release:inspect` validates exact artifacts without commands/writes. `release:stage` uploads only to staging; `release:source`/`release:verify-finalization` validate cross-run evidence and public registry hashes; `release:finalize` alone creates per-package verified-SHA GitHub metadata, with no local tags or npm uploads. These effectful operations require separate owner authorization, activation and clean synchronized main.
- Never substitute dirty/rebuilt/arbitrary artifacts, unchecked registry/API errors or bypass flags. Validate all packages, filenames and SHA-512 hashes before uploads/writes. Persist `attempting` before a stage command; only validated pnpm JSON with a unique UUID and matching name/version/filename/integrity proves `staged`. Nonzero exits, timeouts and invalid receipts leave `unknown`, not permission to retry. Preserve partial receipts and original artifacts; human-authenticated npm reconciliation is required because registry 404 cannot distinguish absent from unapproved stages. No automatic partial staging resume.
- Authenticate the selected source workflow run and attempt, successful verification job, owner actors, exact SHA and artifact ID before finalization. A failed source needs explicit no-upload reconciliation and still requires all five matching public registry integrities. Recheck in the write job; reject conflicting tags, and repair only missing metadata. Keep GitHub API errors sanitized and credentials scoped. See `docs/RELEASING.md` for the frozen-main release window and bounded-history limits.
- Release tests use injected command/registry boundaries and disposable files. They must never run a real publish command, create tags/releases in this repository, or access credentials. Colocated `.test.mjs` files run through `pnpm test scripts/`; use existing Vitest, not another runner.
- `test-packages.mjs` must derive tarball names and overrides from each package's current manifest, not assume common versions or `0.0.0`. It must keep testing actual tarballs, packaged guidance/exports, strict declarations and a Tailwind-free consumer; it never publishes.
- `test-server-compatibility.ts` runs under the pinned Node 26 host with native type stripping; existing `.mjs` scripts retain their runner. `pnpm test:server-compat` needs built server outputs and an explicit installed Node 24.18.0 executable in `LITTLEJAY_NODE24`. Keep both exact runtimes and Fastify versions checked, isolated Node-major typings, lifecycle-script-free fixture installs, bounded loopback listening/cleanup and retained evidence. Do not silently substitute or install runtimes. See `docs/SERVER.md`.
- Its static-hosting fixture stages and hashes the authored API example's configuration/hosting module closure; keep that implementation shared rather than introducing a fixture-only copy of the behavior. Resolve the server from its tarball and Fastify/static plugin from the isolated consumer. Preserve the existing factory/logging checks and all four combinations; this fixture is not #36's combined security/resource/SQLite consumer.
