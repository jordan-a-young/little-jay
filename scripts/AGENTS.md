# Repository scripts

- Read the owning contract and `docs/RELEASING.md` for release work. Keep scripts ESM and package-manager execution on the pinned pnpm; preserve root test configuration and exact dependency conventions.
- `release.mjs` owns release guards and local/CI orchestration; `package-artifacts.mjs` owns version-aware tarball filenames. `release:validate` parses pending notes and checks package/bump allowlists without commands or writes; no notes is valid. `release:version` writes only release files and the lockfile, with no commit/tag/push/publication. `release:check` builds/tests/scans and packs ignored `.release/` output but never uploads. `release:publish` is consequential: explicit activation, exact SHA, clean synchronized main and separate owner permission are required; it creates local tags only after npm confirms every planned package.
- Never substitute a dirty checkout's artifacts, an arbitrary downloaded artifact, an unreviewed branch, unchecked registry errors or a `--no-git-checks`/force flag. Validate the complete allowlist and every artifact before the first upload. On partial publication, keep the report and retry only after checking registry state; versions are immutable.
- Release tests use injected command/registry boundaries and disposable files. They must never run a real publish command, create tags/releases in this repository, or access credentials. Colocated `.test.mjs` files run through `pnpm test scripts/`; use existing Vitest, not another runner.
- `test-packages.mjs` must derive tarball names and overrides from each package's current manifest, not assume common versions or `0.0.0`. It must keep testing actual tarballs, packaged guidance/exports, strict declarations and a Tailwind-free consumer; it never publishes.
